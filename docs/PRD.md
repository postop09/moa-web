# PRD — 모아(Moa)

그래프 중심의 공유 가계부 PWA. 한 가계부를 여러 명이 함께 쓰고, 수입·지출·저축·보험을 기록해 홈 대시보드에서 소비를 분석하며, 달력에서 일정과 지출을 같이 본다.

새 기능을 계획할 때는 이 문서에서 관련 요구사항을 먼저 찾는다. 없으면 이 문서에 항목을 추가한 뒤 작업을 시작한다. 구조·데이터 모델은 [ARCHITECTURE.md](./ARCHITECTURE.md), 인증 흐름은 [authOnboarding.md](./authOnboarding.md), 알려진 결함·개선 과제는 [improvements.md](./improvements.md)를 참고한다.

## 타깃 사용자

가계부를 배우자·가족·룸메이트 등과 공유해서 쓰는 사람. 모바일 우선(PWA로 홈 화면 설치), 한국어 UI, KST(Asia/Seoul) 기준 날짜.

## 용어

| 용어                           | 의미                                                                                   |
| ------------------------------ | -------------------------------------------------------------------------------------- |
| 가계부 (household)             | 거래·일정·카테고리를 공유하는 단위. 한 사용자가 여러 가계부에 속할 수 있음             |
| 소유자 (owner) / 멤버 (member) | 가계부 내 역할. 소유자만 가계부 삭제·멤버 추방 가능                                    |
| 거래 (transaction)             | 수입/지출/저축/보험 중 하나의 기록                                                     |
| 반복 거래 템플릿               | `isRecurring=true, recurringSourceId=null`인 원본 거래. 매달 지정일에 사본을 자동 생성 |
| 자동 생성 사본                 | `recurringSourceId=템플릿 id`인 거래. 일반 거래로 취급되며 반복 토글 UI가 없음         |
| 일정 (schedule)                | 달력에 표시되는 이벤트. 거래와 별개                                                    |
| 일정 카테고리                  | 일정 분류용 색상 태그                                                                  |

## 핵심 기능 요구사항

### FR-ONBOARD — 온보딩·인증

- **FR-ONBOARD-1** Google OAuth로만 로그인한다 (`/login`).
- **FR-ONBOARD-2** 최초 로그인 시 닉네임을 입력해 프로필을 만든다 (`/onboarding/profile`).
- **FR-ONBOARD-3** 프로필 생성 후 가계부가 없으면 새로 만들거나(`/onboarding/household`), 초대 링크(`/invite/{token}`)를 통해 기존 가계부에 합류한다.
- **FR-ONBOARD-4** 온보딩 완료 여부는 쿠키(`moa_gate`)로 캐시해 재방문 시 DB를 다시 조회하지 않는다.
- 상세 상태 전이·리다이렉트 규칙은 [authOnboarding.md](./authOnboarding.md)가 단일 출처.

구현: [`src/pages/login`](../src/pages/login/), [`src/pages/createProfile`](../src/pages/createProfile/), [`src/pages/createHousehold`](../src/pages/createHousehold/), [`src/pages/acceptInvite`](../src/pages/acceptInvite/)

### FR-HOME — 홈 대시보드 (`/`)

월 단위로 가계부 현황을 카드형 차트로 보여준다.

| 카드                     | 내용                                                |
| ------------------------ | --------------------------------------------------- |
| `HouseholdPageTitle`     | 가계부 전환 드롭다운, 인라인 생성                   |
| `MonthNavigator`         | 이전/다음 달 이동. **현재 월 이후로는 이동 불가**   |
| `DashboardHeader`        | 잔액(수입 − 지출 − 저축 − 보험), 유형별 비율 스택바 |
| `MetricRingCard`         | 수입·지출·저축·보험 비율 도넛 4종                   |
| `CategoryPieCard`        | 지출 카테고리 비율 파이 차트                        |
| `TopSpendingsCard`       | 카테고리별 상위 지출 버블 차트                      |
| `SpendingOverTimeCard`   | 주간/월간 지출 추이 스택 막대 (기간 토글)           |
| `DailyExpenseCard`       | 선택한 달의 일별 지출 라인 차트                     |
| `CategoryBudgetCard`     | 카테고리별 예산 대비 사용률·초과 표시               |
| `RecentTransactionsCard` | 이번 달 최근 5건, 클릭 시 `/write/:id`로 이동       |

- **FR-HOME-1** 차트 카드(`CategoryPieCard`/`DailyExpenseCard`/`MetricRingCard`/`SpendingOverTimeCard`/`TopSpendingsCard`)는 ECharts로 렌더링하며 대시보드 진입 시에만 지연 로드한다.
- **FR-HOME-2** 가계부에 거래가 없으면 각 카드는 빈 상태 문구를 보여준다.

> 과거 문서에 있던 "자산 추이"(누적 자산 라인 차트) 카드는 **삭제되었다**. 조회 창(12개월) 밖의 잔액을 무시해 절대값을 오독시키는 문제가 있었고, 대안으로 `DailyExpenseCard`(일일 지출)로 교체됐다 — [improvements.md](./improvements.md) 참고.

구현: [`src/pages/home`](../src/pages/home/)

### FR-WRITE — 거래 작성·수정 (`/write`, `/write/[id]`)

| 필드      | 규칙                                                      |
| --------- | --------------------------------------------------------- |
| 유형      | 지출 / 수입 / 저축 / 보험 중 하나 (필수)                  |
| 금액      | 양의 정수 (필수)                                          |
| 날짜      | DatePicker로 선택 (필수)                                  |
| 카테고리  | 선택한 유형에 맞는 카테고리만 노출, 미선택 가능           |
| 이름      | 선택, 최대 80자                                           |
| 메모      | 선택, 최대 200자                                          |
| 반복 거래 | 토글 on 시 거래 날짜의 **일(day)** 이 매달 반복 기준이 됨 |

- **FR-WRITE-1** 반복 토글은 템플릿(원본)에만 노출되고, 자동 생성 사본에는 노출되지 않는다.
- **FR-WRITE-2** 반복일이 그 달에 없는 날짜(예: 31일)면 그 달의 말일로 보정한다.

구현: [`src/pages/write`](../src/pages/write/) (수정 화면은 [`src/pages/write/edit`](../src/pages/write/edit/)), 배치 로직은 [ARCHITECTURE.md의 반복 거래 인프라](./ARCHITECTURE.md#반복-거래-인프라) 참고.

### FR-CALENDAR — 달력 (`/calendar`)

| 기능             | 설명                                                                                                                                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 월간 그리드      | 일정을 레인으로 배치, 날짜별 지출 합계 표시                                                                                                                                                                                           |
| 이동             | 좌우 스와이프 또는 버튼으로 월/연 단위 이동                                                                                                                                                                                           |
| 필터             | 지출 표시 on/off, 작성자별, 일정 카테고리별                                                                                                                                                                                           |
| 일 상세 패널     | 선택일의 일정·지출 목록, 일정 추가 진입점                                                                                                                                                                                             |
| 일정 CRUD        | 제목, 시작/종료 날짜·시간, 메모, 카테고리                                                                                                                                                                                             |
| 일정 카테고리    | 이름 + 색상 지정, CRUD                                                                                                                                                                                                                |
| 주말·공휴일 표시 | 토·일 요일 헤더와 그리드 날짜 숫자를 빨간색으로 강조, 셀과 그 아래 일정 바 영역까지 열 전체에 옅은 붉은 배경 틴트, 일 상세 패널 제목에 공휴일명 표시. 전/다음 달 패딩 날짜도 주말·공휴일이면 배경 틴트를 받되 숫자는 흐린 회색을 유지 |
| 날짜 그리드 격자 | 날짜 셀과 일정 바 영역을 간격 없이 배치하고 옅은 회색 격자선(세로·가로 모두)으로 구분                                                                                                                                                 |

- **FR-CALENDAR-1** 멤버별 색상은 가계부 멤버 목록 순서를 인덱스로 배정한다 — 멤버가 탈퇴하면 이후 멤버들의 색이 밀리는 알려진 한계가 있다 ([improvements.md](./improvements.md) 참고).
- **FR-CALENDAR-2** 공휴일 데이터는 `@hyunbinseo/holidays-kr`(공식 월력요항 기반, 대체·임시공휴일 포함) 패키지의 정적 데이터를 쓴다. 특정 연도까지만 데이터가 있으므로(현재 2018~2027년) 매년 `pnpm update`로 최신화가 필요하다.
- **FR-CALENDAR-3** 주말·공휴일 배경 틴트는 이번 달과 전/다음 달 패딩 날짜 모두에 적용한다. 다만 날짜 숫자 색상(빨간 글씨)은 이번 달 날짜(`inMonth`)에만 적용하고, 패딩 날짜는 흐린 회색을 유지한다 — 이 조합은 20% 배경 틴트 위에서 대비가 1.55:1로 WCAG AA(4.5:1) 미달이지만, "이번 달이 아님"이라는 정보가 더 중요하다고 판단해 의도적으로 허용한 트레이드오프다. 셀 배경은 항상 `--color-surface` 기준으로 합성해 격자선 색과 섞이지 않도록 한다(재사용 시 배경이 달라지면 대비 재검증 필요).

구현: [`src/pages/calendar`](../src/pages/calendar/)

### FR-SUPPORT — 고객센터·1:1 문의 (`/support/**`, 로그인 사용자)

설정 > 도움말 > 고객센터로 진입한다. `proxy.ts`가 비로그인을 `/login`으로 보내고, FAQ도 로그인 사용자에게만 열린다. 운영자 응대는 [FR-ADMIN](#fr-admin--어드민-문의-관리-admin-운영자)이 맡는다.

| 경로                           | 화면         | 내용                                                                                                                                           |
| ------------------------------ | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `/support`                     | 고객센터 홈  | 운영자 사칭 주의 문구, FAQ 검색, 카테고리 칩, FAQ 목록(펼침), 내 문의 내역 링크(새 답변 배지), 하단 고정 "1:1 문의하기" CTA                    |
| `/support/inquiries/new`       | 문의 작성    | 제목·내용·사진·기기 정보 동의. 쿼리로 모드 전환: `?followUp=<문의 id>` 추가 문의, `?edit=<문의 id>` 수정 (uuid가 아니면 새 문의로 취급)        |
| `/support/inquiries/[id]/done` | 접수 완료    | "문의가 접수됐어요", 분류됐으면 "{카테고리} 문의로 접수됐어요" 칩, 안내 문구(내 문의에서 확인, 평일 기준 1일 이내 답변), "내 문의 보기"/"확인" |
| `/support/inquiries`           | 내 문의 목록 | 탭 전체/답변 대기/답변 완료/종결(`?status=`), 새 답변이 있는 문의 우선 + 최신순, 20건씩 무한 스크롤, 빈·오류 상태                              |
| `/support/inquiries/[id]`      | 문의 상세    | 상태·카테고리·접수일, 대화 스레드(질문·운영자 답변·추가 문의, 사진 보기), 별점, 수정·삭제, 하단 바(추가 문의/해결됐어요, 종결 시 새 문의하기)  |

- **FR-SUPPORT-1** FAQ는 카테고리 칩(전체 + 7개)으로 거르고 서버가 정한 순서(`helpfulCount` 내림차순, `sortOrder` 오름차순)로 최대 10건 보여준다. 검색은 질문·답변 본문 부분 일치이며 2자 이상일 때만 300ms 디바운스로 조회하고, 검색 중에는 칩이 비활성화돼 "전체에서 검색 중"으로 범위를 알린다. 초기 FAQ 데이터는 마이그레이션 시드(10건)다.
- **FR-SUPPORT-2** 로딩·오류·빈 상태(FAQ 없음/검색 결과 없음/내 문의 없음/탭별 없음)를 모든 목록 화면이 구분해 보여준다.

#### 문의 상태

내부 상태는 4개이며, 사용자 앱에서는 `in_progress`를 따로 보이지 않고 "답변 대기"로 합쳐 보여준다.

| 내부 상태     | 사용자에게 | 운영자에게 | 진입 조건                                                         |
| ------------- | ---------- | ---------- | ----------------------------------------------------------------- |
| `waiting`     | 답변 대기  | 답변 대기  | 접수 직후, 추가 문의 직후, 운영자가 되돌렸을 때                   |
| `in_progress` | 답변 대기  | 처리 중    | 운영자가 답변 대기 문의 상세를 열어 담당자로 지정됐을 때          |
| `answered`    | 답변 완료  | 답변 완료  | 운영자가 답변을 등록했을 때                                       |
| `closed`      | 종결       | 종결       | 사용자가 "해결됐어요"를 눌렀거나 운영자가 사유와 함께 종결했을 때 |

- **FR-SUPPORT-3** 상태 전이는 모두 DB RPC가 검증한다(허용되지 않으면 `invalid_state`). 사용자가 일으키는 전이는 추가 문의(`answered` → `waiting`)와 해결됐어요(`answered` → `closed`) 둘뿐이다. 종결된 문의는 이어갈 수 없고 하단에 "새 문의하기"만 노출한다.

#### 카테고리

| 키                 | 라벨          |
| ------------------ | ------------- |
| `shared_household` | 공유 가계부   |
| `record_category`  | 기록·카테고리 |
| `stats_screen`     | 통계·화면     |
| `account_login`    | 계정·로그인   |
| `bug_report`       | 오류 신고     |
| `feature_request`  | 기능 제안     |
| `other`            | 기타          |

| 사진      | 최대 3장, 장당 10MB, JPG/PNG/WebP/HEIC(HEIF). 새 문의·추가 문의에서만 첨부하고, 수정에서는 첨부를 바꿀 수 없다                                          |
| 기기 정보 | "앱·기기 정보 함께 보내기" 체크박스(기본 선택, 새 문의에서만). 항목: 앱 버전, OS, 기기 모델, 언어. 가계부 내역·금액은 보내지 않으며 운영자만 볼 수 있다 |

- **FR-SUPPORT-4** 제목·내용은 앞뒤의 공백·탭·줄바꿈만 제거한 뒤 코드포인트 수로 센다(DB의 `btrim`/`char_length`와 같은 기준이라 클라이언트와 서버 판정이 어긋나지 않는다). 사진 검사는 개수 → 형식 → 크기 순으로 거절하며, 일부 브라우저가 HEIC의 MIME을 비워 보내면 확장자로 판단한다.
- **FR-SUPPORT-5** 임시저장은 없다. 작성 중 내용(제목·내용 변경 또는 사진 선택)이 있으면 뒤로 가기 시 "작성 중인 내용이 사라져요" 확인을 띄우고, 탭 닫기·새로고침은 브라우저 `beforeunload` 확인으로 막는다.
- **FR-SUPPORT-6** 제출 실패는 제출 바 위 인라인 알림으로 한 번만 안내하고 버튼을 다시 연다. 사진은 먼저 올리고 RPC가 확정 거절하면 올린 파일을 정리한다. 네트워크 오류처럼 서버가 처리했는지 알 수 없을 때는 파일을 남긴다. 수정 중 상태가 바뀌어 수정 불가가 되면 토스트로 알리고 상세로 보낸다.

#### Jev 자동 분류

- **FR-SUPPORT-7** 새 문의에서만 동작한다. 내용이 10자 이상이면 입력이 800ms 멈춘 뒤 **예비 분류**를 호출하고, 결과 카테고리의 FAQ를 최대 3건 "관련 도움말"로 추천한다(추천은 저장하지 않는다). 사용자가 찾는 답이 없으면 그대로 접수한다.
- **FR-SUPPORT-8** **최종 분류**는 접수 시점에 제목+내용으로 한 번 더 호출하고(5초 타임아웃) 결과를 문의에 저장한다. 신뢰도가 **0.5 이상**이면 그 카테고리로, 미만이거나 알 수 없는 값이면 미분류로 저장한다(미분류일 때 신뢰도는 저장하지 않는다).
- **FR-SUPPORT-9** 분류 실패(키 없음·타임아웃·네트워크·응답 형식 오류·비로그인 등)는 항상 미분류로 처리하며 **접수를 막지 않는다**.
- **FR-SUPPORT-10** 작성 화면에 "입력한 내용은 문의 분류를 위해 외부 AI 서비스로 전송돼요."를 고지한다. 수정 모드는 분류를 다시 하지 않는다.

#### 새 답변 알림·읽음

- **FR-SUPPORT-11** 새 답변 신호는 **앱 내 배지뿐**이다(푸시·이메일 없음). 읽지 않은 답변이 있는 문의 수를 설정 > 고객센터와 고객센터 홈의 "내 문의 내역"에 "새 답변 N"으로, 목록 카드에는 "새 답변"으로 표시한다.
- **FR-SUPPORT-12** 운영자가 답변하면 문의가 "읽지 않음"이 되고, 사용자가 답변이 보이는 상태로 상세를 열면 읽음 처리돼 배지가 꺼진다(실패해도 알리지 않는다). 추가 문의·해결됐어요도 읽지 않음을 해제한다. 개수는 조회 시점 기준이며 실시간 갱신은 없다.

#### 수정·삭제·별점·해결

| 동작       | 허용 조건                                          | 비고                                                              |
| ---------- | -------------------------------------------------- | ----------------------------------------------------------------- |
| 수정       | 상태가 `waiting`이고 운영자 답변이 한 번도 없을 때 | 제목·내용만. 수정하면 운영자 쪽 답변 충돌 검사에 걸리도록 갱신됨  |
| 추가 문의  | `answered`일 때                                    | `waiting`으로 돌아가고 대기 시간을 다시 센다                      |
| 해결됐어요 | `answered`일 때                                    | 확인 후 `closed`                                                  |
| 별점(1–5)  | 운영자 답변이 있고 `answered`/`closed`일 때        | 문의당 **한 번**, 저장 후 읽기 전용. 답변 없이 종결된 문의는 불가 |
| 삭제       | 본인 문의라면 상태와 무관하게 가능                 | 답변·메시지도 함께 삭제되며 되돌릴 수 없다는 확인을 거친다        |

- **FR-SUPPORT-13** 삭제는 DB 행(메시지는 cascade)을 먼저 지우고 첨부 Storage 객체는 best-effort로 정리한다. 정리가 실패하면 고아 파일이 남을 수 있다(알려진 한계).

### FR-ADMIN — 어드민 문의 관리 (`/admin/**`, 운영자)

운영자가 사용자 문의를 큐로 받아 분류·답변·종결한다. 사용자 앱과 별도 셸(`widgets/adminShell`, 어두운 사이드바이며 좁은 화면에서는 상단 바)을 쓰며 `/admin`은 `/admin/inquiries`로 이동한다.

- **FR-ADMIN-1** 운영자는 `admins` 테이블에 등록된 로그인 사용자다(SQL로 직접 등록, 앱에 등록 화면 없음). `/admin/**`은 로그인(`proxy.ts`) 뒤 레이아웃이 `is_admin` RPC로 확인하며, 운영자가 아니거나 확인에 실패하면 존재를 숨기려고 **404**를 돌려준다. 운영자도 일반 온보딩(프로필·가계부)을 마쳐야 들어올 수 있다.
- **FR-ADMIN-2** 사이드바에 "문의 관리"가 있고, 미처리 건수(답변 대기 + 처리 중)를 배지로 보여준다(99 초과는 `99+`, 1분마다 갱신). "FAQ 관리"·"답변 템플릿"·"통계"는 "준비 중"으로 비활성이다.

#### 문의 목록 (`/admin/inquiries`)

| 열       | 내용                                                                                    |
| -------- | --------------------------------------------------------------------------------------- |
| 상태     | 운영자용 라벨(답변 대기/처리 중/답변 완료/종결)                                         |
| 카테고리 | 라벨, 없으면 "미분류"                                                                   |
| 제목     | 상세로 가는 링크(행 클릭도 이동)                                                        |
| 신뢰도   | Jev 분류 신뢰도(소수 둘째 자리), 없으면 `—`. 정렬 가능                                  |
| 대기     | 열린 문의(답변 대기·처리 중)만 경과 시간 표기, **24시간 초과**면 "초과" 표시. 정렬 가능 |
| 담당자   | 담당 운영자 이메일의 아이디 부분                                                        |

- **FR-ADMIN-3** 필터·정렬·쪽은 모두 **URL 쿼리**가 단일 출처이며(`status`/`category`/`uncategorized`/`period`/`q`/`sort`/`dir`/`page`/`size`) 바꿀 때 `router.replace`로 히스토리를 쌓지 않는다. 기본값과 같은 항목은 쿼리에서 생략하고, 알 수 없는 값은 기본값으로 되돌린다. 필터를 바꾸면 1쪽으로 돌아간다.
- **FR-ADMIN-4** 기본 필터는 상태 "답변 대기 + 처리 중", 대기 정렬 오름차순, 20건/쪽이다. 상태는 최소 1개가 선택돼 있어야 한다. "미분류만"을 켜면 카테고리 선택이 잠긴다.
- **FR-ADMIN-5** 기간 기본값은 상태에 따라 달라진다. 열린 상태(답변 대기·처리 중)만 보면 **전체 기간**, 답변 완료·종결이 하나라도 섞이면 **최근 30일**이다. 선택지는 최근 7/30/90일·전체이고, 명시한 값은 기본 규칙보다 우선한다.
- **FR-ADMIN-6** 대기 정렬은 **큐 순서**다. 방향과 관계없이 답변 대기가 처리 중보다 먼저, 그 밖의 상태는 그 뒤에 놓고 각 그룹 안에서 대기 시작 시각을 정렬한다(오름차순 = 오래 기다린 순). 신뢰도 정렬은 신뢰도가 없는 문의를 항상 마지막에 둔다. `sort=createdAt`(접수일)도 URL·RPC에서 지원하지만 열 헤더 정렬은 없다.
- **FR-ADMIN-7** 키워드는 2자 미만이면 무시하고(300ms 디바운스, Enter는 즉시), 제목과 모든 메시지 본문(내부 메모 포함)의 부분 일치로 찾는다. 쪽 크기는 20/50/100이며, 결과가 없는데 `page > 1`이면 1쪽으로 보내고 토스트로 알린다.
- **FR-ADMIN-8** 로딩(이전 결과 유지)·오류(권한 없음·로그인 만료 문구 구분)·빈 상태(기본 필터면 "지금 처리할 문의가 없어요." + 최근 답변 완료 보기, 아니면 필터 초기화)를 구분한다.

#### 문의 상세 (`/admin/inquiries/[id]`)

- **FR-ADMIN-9** 스레드는 사용자 질문·추가 문의·운영자 답변과 **내부 메모**를 시간순으로 보여주며, 메모는 "사용자에게 보이지 않음"으로 구분한다. 첨부 사진은 `attachmentGallery`로 본다. 헤더에 접수일·대기 시간·24시간 초과·담당자·카테고리를 표시한다.
- **FR-ADMIN-10** 작성 영역은 "답변"과 "내부 메모" 탭이다. 답변은 본문 1–2000자, 사진 최대 3장(규칙은 사용자와 동일)이며 등록 전 **미리보기 확인**(본문·첨부 장수)을 거친다. 메모는 1–2000자이고 미리보기 없이 저장한다. 종결된 문의는 작성 영역 대신 종결 안내(사유 포함)만 보인다.
- **FR-ADMIN-11** 답변 첨부는 **문의 작성자 폴더**(`{문의 작성자 id}/…`)에 올린다. 그래야 사용자가 읽을 수 있다. 서버는 그 폴더 아래 경로만 허용한다.
- **FR-ADMIN-12** **충돌 처리**: 미리보기를 연 시점의 마지막 메시지(메모 제외)와 문의 수정 시각을 함께 보내, 그 뒤 다른 운영자가 답변했거나 사용자가 문의를 수정·추가했으면 서버가 `conflict`로 거절한다. 화면은 "다른 운영자가 먼저 답변했어요. 내용을 확인해주세요." 안내와 새로고침을 보여주고, 최신 상태를 받을 때까지 낡은 기준으로 재등록하지 못하게 막는다. 화면이 알고 있던 값이 이미 달라졌으면 업로드·요청 없이 충돌로 처리한다.
- **FR-ADMIN-13** **카테고리를 먼저 지정해야 답변할 수 있다**(미분류면 `uncategorized`로 거절). 미분류 문의는 답변 영역에 안내 배너가 뜨고 카테고리 선택이 처음부터 펼쳐져 있다. 카테고리 변경은 별도 저장이며, Jev 신뢰도를 함께 보여준다.
- **FR-ADMIN-14** **상태·담당자는 "저장" 단계를 거친다.** 고르는 즉시 저장하지 않고 초안으로 두었다가 저장하면 서버 값과 달라진 항목만 한 번에 보낸다. 직접 고를 수 있는 상태는 답변 대기·처리 중뿐이며(답변 완료·종결은 현재 값일 때만 표시), 담당자는 운영자 목록에서 고른다. 초안이 있는 동안 다른 곳에서 문의가 바뀌면 초안을 버리고 알린다. 답변 완료를 답변 대기로 되돌리면 대기 시간을 다시 센다.
- **FR-ADMIN-15** **열 때 자동 담당**: 마운트 뒤 새로 받은 결과가 "답변 대기"이면 한 번 `처리 중` + 내가 담당으로 바꾼다. 다른 운영자가 먼저 담당했어도 요청은 성공하며, 화면은 결과가 "처리 중 + 내가 담당"일 때만 알린다. **미리보기(peek)** 모드(`?peek=1`, 사이드 패널의 "이전 문의"가 새 탭으로 열 때 사용)는 열지도 담당자를 지정하지도 않는다. 실패해도 화면은 막지 않고 담당자 직접 지정을 안내한다.
- **FR-ADMIN-16** **종결**은 사이드 패널의 "종결 처리"에서 사유를 골라야 한다(중복 문의·스팸·광고·테스트·기타, 기타는 직접 입력 필수, 최대 500자). 사용자에게는 종결된 문의로만 보이고 사유는 운영자에게만 보인다. 종결 후에는 카테고리·상태·담당자를 바꿀 수 없다.
- **FR-ADMIN-17** 사이드 패널에는 기기 정보(앱 버전·OS·기기·언어, 값이 있으면 오류 코드·진입 화면·마지막 동기화), 같은 사용자의 이전 문의(최근 5건, 새 탭 미리보기), 담당자 드롭다운용 운영자 목록이 있다.
- **FR-ADMIN-18** 답변·메모·상태 저장 후에는 상세·스레드·이전 문의·미처리 건수·목록을 서버 상태로 다시 맞춘다. 작성 중 내용이나 저장하지 않은 상태·담당자 변경이 있으면 `beforeunload` 확인을 띄운다.

### FR-NAV — 앱 네비게이션

하단 탭(모바일)/사이드바(데스크톱) 4개: **홈**(`/`), **내역**(`/history`), **달력**(`/calendar`), **설정**(`/settings`) — [`src/shared/config/navItems.ts`](../src/shared/config/navItems.ts). 거래 작성은 FAB 버튼 또는 `/write` 직접 접근으로 진입한다. 고객센터는 탭이 아니라 설정 화면의 도움말 섹션으로 진입하며, `/write`와 `/support/**`에서는 FAB을 숨긴다. 어드민(`/admin/**`)은 `AppShell` 밖이라 이 탭·사이드바를 쓰지 않는다([FR-ADMIN](#fr-admin--어드민-문의-관리-admin-운영자) 참고).

### FR-PWA — PWA 설치

홈 화면에 설치해 앱처럼 쓸 수 있다. `@ducanh2912/next-pwa` 기반, `public/manifest.json`. 설치 유도 프롬프트는 [`src/features/pwaInstall`](../src/features/pwaInstall/)가 담당하며 `/welcome`에 설치 가이드 섹션이 있다.

## 비기능 요구사항

- **언어**: UI는 한국어 전용. `<html lang="ko">`.
- **디바이스**: 모바일 우선 반응형. PWA로 설치 가능해야 한다.
- **시간대**: 반복 거래 배치·날짜 경계 계산은 KST(Asia/Seoul) 기준. 단, 클라이언트 UI의 로컬 날짜 표시는 브라우저 타임존을 쓴다 — 해외 사용자에게는 경계가 어긋날 수 있는 알려진 한계 ([improvements.md](./improvements.md)).
- **접근성**: WCAG 2.2 AA를 지향한다. 전용 리뷰어(`.claude/agents/a11y-reviewer.md`)가 UI 변경마다 점검한다.
- **보안**: 가계부 간 데이터 격리는 Supabase RLS에 의존한다(클라이언트가 publishable 키로 직접 테이블에 접근).
- **보안(문의·어드민)**: 문의 테이블은 RLS와 **컬럼 단위 SELECT 권한**을 함께 쓰고 쓰기는 모두 `SECURITY DEFINER` RPC로만 한다(직접 INSERT/UPDATE 불가). 운영자도 같은 `authenticated` 롤이라 내부용 컬럼(종결 사유·분류 신뢰도·담당자·메시지 작성자)은 직접 읽지 못하고, 어드민 화면은 `is_admin()`을 검사하는 `SECURITY DEFINER` RPC로만 읽는다. 첨부는 private 버킷 + 서명 URL(1시간)이며, 다른 사용자의 문의 제목·운영자 이메일이 담긴 어드민 쿼리(`['admin', ...]`)와 서명 URL 쿼리는 `localStorage` 영속 캐시에서 제외한다. `/admin`·`/support`는 `robots.txt` disallow와 `noindex`로 색인을 막는다.
- **콜드 스타트**: 설치형 PWA를 완전히 종료한 뒤 다시 실행해도(iOS standalone 포함) 로그인·온보딩이 끝난 사용자는 리다이렉트 없이 `/`가 한 번의 요청으로 응답해야 하며, 마지막으로 본 대시보드는 네트워크 응답 전에 기기 캐시(24시간, 로그아웃 시 삭제)로 즉시 그려진 뒤 백그라운드에서 갱신된다. 데이터가 없을 때는 텍스트 대신 레이아웃과 같은 모양의 스켈레톤을 보여주고, iOS 스플래시는 주요 iPhone·iPad 해상도를 모두 커버한다.

## 범위 밖 / 미결정

- 다크 모드 — 디자인 토큰에 다크 테마 정의 없음
- 다국어(i18n)
- 오프라인 쓰기(PWA는 설치만 지원, 오프라인 데이터 동기화는 없음)
- 예산 초과 알림(푸시/이메일)
- 통계 전용 화면 — `/stats` 라우트는 현재 `redirect('/history')`만 하는 스텁이다 ([`app/(app)/stats/page.tsx`](<../app/(app)/stats/page.tsx>))
- 문의 답변 푸시 알림 — 새 답변 신호는 앱 내 배지뿐이다
- CS-06 오류 안내 다이얼로그에서 문의로 들어오는 진입점 — 어드민이 보여줄 수 있는 `errorCode`·`entryScreen`·`lastSyncedAt` 항목은 있지만 작성 화면이 아직 수집하지 않는다
- FAQ 비로그인 열람 — FAQ는 로그인 사용자에게만 열려 있다
- 어드민 2차 범위: FAQ 관리, 답변 템플릿, 통계 (사이드바에 "준비 중"으로만 존재)
- 첨부 열람 기록 — 운영자가 사진을 열람한 이력을 남기지 않는다
- 작업 로그 화면 — 분류·상태·담당자 변경은 `inquiry-events`에 기록되지만 이를 보여주는 화면은 없다
- 상태·담당자·카테고리 변경(`admin_update_inquiry_meta`)의 서버 쪽 expected-updatedAt 검사 — 낡은 초안 방지는 현재 클라이언트가 맡는다
- 고아 첨부 파일 정리 배치 — 삭제·실패 정리는 클라이언트 best-effort뿐이다
- Jev 외부 전송에 대한 개인정보처리방침 개정 — 작성 화면 고지만 있고 `/privacy` 본문은 갱신되지 않았다
- 운영자 계정의 온보딩 면제 — 운영자도 일반 온보딩(프로필·가계부)을 마쳐야 `/admin`에 들어올 수 있다
